# 子供向け足し算・引き算練習Web 仕様書

本書は [01_requirements.md](./01_requirements.md) の要件を実装可能なレベルまで具体化した仕様書である。

## 1. 概要

- 小学一年生向けの足し算・引き算練習Webアプリ。
- 問題を1問ずつ表示し、全20問を解き終えると正解数を表示する。
- スマホ・タブレットでの利用を前提とし、回答はワンタップの4択ボタンで入力する。
- 正解時などに子供の興味をひく楽しいエフェクトを表示する。

### 1.1 モード一覧

| モード | 内容 |
|---|---|
| 単純足し算モード | 足し算 20問 |
| 単純引き算モード | 引き算 20問(答えは常に0以上) |
| 文章題モード | 足し算・引き算になる文章題 20問 |

### 1.2 レベル一覧

モードとは独立に、出題する数の範囲を選べる。ホーム画面でモードを選ぶ前にレベルを選択する。

| ボタン表示 | レベル | 内容 |
|---|---|---|
| かんたん | `single-digit` | 一桁(1〜9)の数のみで出題。答えが10を超える繰り上がり(例: 8+7=15)は引き続き出題される。 |
| ちょいむず | `up-to-19` | 19までの数を使って出題。二桁の数(10〜18)を含む足し算・引き算、繰り上がり・繰り下がり(例: 15-8=7)を含む。 |

## 2. 画面仕様

画面はSPA内の3画面で構成する。ページ遷移(URL変更)は行わず、アプリ内の状態で切り替える。

### 2.1 ホーム画面

- アプリタイトルを表示する。
- 「むずかしさ」「モード」の見出しでグループ分けし、選択の対象を混同しないようにする。
  - むずかしさ: レベル選択ボタンを2つ横に並べる:「かんたん」「ちょいむず」。
  - モード: モード選択ボタンを3つ縦に並べる:「たしざん」「ひきざん」「ぶんしょうだい」。
- ボタンは子供が押しやすいよう大きく(高さ64px以上)、色分けする。
- モードボタンをタップした時点で選択中のむずかしさが確定し、問題画面へ遷移する。
- 前回選んだモード・むずかしさを記憶し、次にホーム画面を開いた時に選択済みの状態にする(むずかしさは選択状態を復元、モードは直前に選んだボタンに目印を表示)。初回訪問時はむずかしさ「かんたん」・モードは目印なしとする。
- 文言はすべてひらがなとする。

### 2.2 問題画面

- 上部に進捗を表示する(例: 「5 / 20」およびプログレスバー)。
- 中央に問題を表示する:
  - 計算モード: 数式を大きく表示(例: 「3 + 2 = ?」)。
  - 文章題モード: 文章を表示(例: 「いちごが 3 こ あります。…」)。文字サイズは大きめ、分かち書きで表示する。
- 下部に回答用の4択ボタンを2×2グリッド表示する(仕様は「4. 入力UI仕様」参照)。
- 回答すると正誤フィードバック(「5. エフェクト仕様」参照)を表示し、自動で次の問題へ進む。
- 左上に「やめる」ボタンを置き、タップでホーム画面に戻る(このセッションの結果は保存しない)。

### 2.3 結果画面

- 正解数を大きく表示する(例: 「20もんちゅう 17もん せいかい!」)。
- 正解数に応じたお祝いエフェクトを表示する(「5. エフェクト仕様」参照)。
- ボタンを2つ表示する:
  - 「もういちど」: 同じモードで新しい20問を開始する。
  - 「ホームへ」: ホーム画面に戻る。

## 3. 出題仕様

### 3.1 単純足し算モード

- `a + b` の形式。
- 9までのかず: `a`, `b` はそれぞれ 1〜9 の乱数。答えの範囲は 2〜18(繰り上がりを含む)。
- 19までのかず: `a + b ≦ 19` となるよう `a` は 1〜18、`b` は 1〜(19-`a`) の乱数。答えの範囲は 2〜19。二桁の数(10〜18)を含む組み合わせと、一桁同士で繰り上がる組み合わせ(例: 8+7)の両方が出題され得る。

### 3.2 単純引き算モード

- `a - b` の形式。答えが常に 0 以上になるよう `a ≧ b` で生成する。
- 9までのかず: `a` は 1〜9、`b` は 0〜a の乱数(答えの範囲は 0〜9)。
- 19までのかず: `a` は 1〜19、`b` は 0〜a の乱数(答えの範囲は 0〜19)。繰り下がりを伴う組み合わせ(例: 15-8)も出題され得る。

### 3.3 文章題モード

実行時に生成AIは呼び出さない(インフラコスト最小化のため)。開発時に生成AIで作成したテンプレートプールをアプリに同梱し、実行時にテンプレートへ乱数で数値・題材を差し込んでバリエーションを出すハイブリッド方式とする。

- テンプレートは合計100種類(足し算系50種・引き算系50種)を開発時に生成AIで作成し、静的データ(TypeScriptモジュール `wordTemplates.ts`)としてアプリに同梱する。
- テンプレートはプレースホルダ `{item}`(題材名)・`{a}`・`{b}`(数値)・`{c}`(助数詞)を含む文字列とする。
  - 例(足し算 add-01): 「{item}が {a} {c} あります。そこへ {b} {c} ふえました。{item}は ぜんぶで なん{c} に なりましたか?」
  - 例(引き算 sub-01): 「{item}が {a} {c} あります。そのうち {b} {c} たべました。{item}は なん{c} のこって いますか?」
- 題材(`{item}`)は小学生が興味を持つものを19種類用意する(例: いちご、みかん、あめ、たまご、どんぐり、ふうせん、けしゴム、シール、おりがみ、ミニカー)。題材ごとに助数詞(`{c}`: こ・まい・だい)を対応付ける。
- テンプレートと題材の組み合わせは、不自然な文(例: 食べられない題材に「たべました」を使う)を避けるため、タグ方式で制約する。
  - 題材には性質タグ(`ItemTag`)を1つ以上付与する: `edible`(たべられる)・`usable`(つかう動作が自然)・`buyable`(売り買いの文に使える)・`pickable`(ひろうのが自然)・`collectible`(あつめる対象)・`craftable`(じぶんでつくる)・`growable`(はたけで とれる)・`light`(かるくて かぜで とぶ)・`round`(まるくて ころがる)・`colored`(色ちがいが自然)・`tree`(木になる)。
  - テンプレートは `requires` に必要なタグを配列で指定できる(省略時はすべての題材から選択可)。出題時は `requires` の全タグを満たす題材の中からランダムに1つを選んで差し込む。
  - 全テンプレートについて、条件を満たす題材が最低1つ以上存在することをユニットテストで保証する。
- 数値 `a`, `b` は 3.1・3.2 と同じレベル別ルールで生成する。ただし引き算系の `b` は「0こ たべました」のような不自然な文を避けるため 1〜`a`(0を含まない)とする。そのため文章題の引き算の答えは、9までのかずでは 0〜8(3.2の等式引き算は 0〜9)、19までのかずでは 0〜18(3.2の等式引き算は 0〜19)の範囲になる。
- 1セッション20問は足し算系・引き算系を混合して出題する(各10問、順序はランダム)。
- 文はひらがな中心・分かち書きとし、小学一年生が読めるようにする。

### 3.4 共通ルール

- 1セッション内で同一の問題(計算モードでは同一の式、文章題では同一のテンプレート×数値の組)は出題しない。
- 20問を生成してからセッションを開始する。

## 4. 入力UI仕様

- 回答は選択ボタンのワンタップで確定する。確定ボタンやテキスト入力は設けない。
- 回答は4択とする(正解1つ+誤答3つ、重複なし)。誤答は問題の演算に応じた範囲からランダムに選び、4つの選択肢はシャッフルして表示位置をランダム化する。
  - 誤答の生成範囲は、その問題の演算・レベルに合わせる:
    - 9までのかず: 足し算(文章題の足し算含む)は 0〜18、引き算(文章題の引き算含む)は 0〜9 の範囲から生成。
    - 19までのかず: 足し算・引き算(文章題含む)ともに 0〜19 の範囲から生成。
  - 誤答の生成範囲は演算・レベルごとの固定範囲であり、必ずしもその問題の実際の答えの取りうる範囲(3.1〜3.3参照)と一致しない(例: 文章題の引き算は答えの上限が実際の等式引き算より1小さいが、誤答は等式引き算と同じ範囲から選ばれ得る)。
- 選択ボタンは2×2のグリッドで表示する。
- ボタンは指で押しやすい正方形サイズ(最小 96×96px、間隔 16px)とする。
- タップ後は正誤フィードバック表示中の誤操作を防ぐため、全ボタンを一時的に無効化する。

## 5. エフェクト仕様

### 5.1 正解時

- 大きなマル(⭕)を表示し、紙吹雪(36個)などの楽しいアニメーションを再生する(約1秒)。
- 短いメッセージをランダムに表示する: 「せいかい!」「やったね!」「すごい!」「ピンポーン!」「そのちょうし!」「てんさい!」。
- 効果音は本実装では未実装(将来対応の余地あり)。

### 5.2 不正解時

- バツ(❌)と正しい答えを表示する(例: 「こたえは 5 だよ」、約1.5秒)。
- 子供を責めない・怖がらせない演出とする(派手な失敗音や赤の点滅は使わない)。

### 5.3 結果画面

- 正解数に応じて演出を変える:
  - 20問正解: 特別なお祝い演出(大量の紙吹雪+トロフィー表示など)。
  - 15問以上: 紙吹雪+星の演出。
  - それ未満: 「よくがんばったね!」の応援演出。

## 6. データ保存仕様(LocalStorage)

DBは使用せず、ブラウザの LocalStorage にプレイ履歴を保存する。

- キー: `math-practice/history`
- 値: プレイ履歴の配列(JSON文字列)。1セッション終了ごとに1件追記する。

```json
[
  {
    "playedAt": "2026-07-23T10:30:00+09:00",
    "mode": "addition",
    "level": "single-digit",
    "correctCount": 17,
    "totalCount": 20
  }
]
```

- `mode` は `addition` | `subtraction` | `word-problem`。
- `level` は `single-digit`(ボタン表示「かんたん」) | `up-to-19`(ボタン表示「ちょいむず」)。`level` 追加前に保存された旧データを読み込む際は `single-digit` として扱う。
- 履歴は最新100件まで保持し、超過分は古いものから削除する。
- 途中で「やめる」を押したセッションは保存しない。
- 履歴の集計・グラフ表示は将来拡張とする(本仕様の範囲外)。

### 6.1 前回の選択(LocalStorage)

ホーム画面で前回選んだモード・むずかしさを記憶し、次回ホーム画面を開いた時に復元する。

- キー: `math-practice/last-selection`
- 値: `{ "mode": "addition", "level": "single-digit" }` の形式(直前にモードボタンをタップした時点の選択を保存)。

## 7. 技術仕様

- **フロントエンド**: Vite + React(TypeScript)による静的SPA。
- **ホスティング**: Cloudflare Pages に静的デプロイ。Workers・DB・サーバーサイド処理は使用しない(インフラコスト最小化)。
- **データ保存**: LocalStorage のみ(「6. データ保存仕様」参照)。
- **対応端末**: スマホ縦持ちを基準にデザインし、タブレットにも対応するレスポンシブレイアウトとする。
- **対応ブラウザ**: iOS Safari / Android Chrome の最新版を主対象とする。
- **オフライン動作**: 静的アセットのみで動作するため、初回ロード後は通信不要。
